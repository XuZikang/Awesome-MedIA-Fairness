# 每周文献审核：推荐用 Markdown

每周日北京时间 10:07，程序检索文献并更新 `reports/review-latest.md`。审核单包含尚未收录文章的稳定编号、原文链接、中文概述、模型建议、证据限制和五项原文证据。机器建议与人工决定分开保存，默认全部为“待审核”；周更不会把任何新增文章自动写入 README。

## 方式一：直接在聊天里给出决定

打开 [最新审核单](../reports/review-latest.md)，复制文章编号和标题，在这个聊天中回复，例如：

```text
通过：p-0123456789abcdef0123，分类改为 In-processing。
排除：p-123456789abcdef01234，不涉及医疗算法公平性。
暂缓：p-23456789abcdef012345，需要查看全文。
其余保持待审核。
```

以上编号只是格式示例，请复制审核单中的实际编号。也可以使用“本周审核单的第几篇 + 完整标题”；稳定编号更不容易产生歧义。如果同一文章的证据已更新，我会先指出变化并让你重新确认，不把旧决定套用到新版本。

## 方式二：修改 Markdown 文件后交给我

下载或打开 `reports/review-latest.md`，只修改每篇的两行：

```text
审核决定：通过
审核备注：保留；分类改为 Post-processing，摘要第二句需要强调推理时干预。
```

可选决定：**待审核、通过（或纳入）、排除、暂缓**。保留文章编号、标题和“证据版本”行即可。把修改后的 `.md` 文件附在聊天中，或将它另存到本地并告诉我完整路径；如果直接在 GitHub 编辑提交审核单，也请在聊天中告诉我文件链接。无需整理成 Word 或 Excel，不需要改英文 README。

## 你审核后，我如何处理

1. 核对编号、原文和当前证据版本，保留你的备注。
2. “通过”：按你的分类和文字修改意见生成三句英文 TLDR，验证原文证据、日期和重复记录，加入 README。
3. “排除”：保存排除理由，不收录；“暂缓／待审核”：留在候选中。
4. 运行目录检查和测试，提交通过的条目及审核记录到 GitHub；向你回报新增与暂缓数量。

审核通过但仍缺少必要原文证据的文章，会先补核并报告具体缺口。你可以同时指定分类、英文摘要修改、代码链接或重复版本合并意见。

## 历史与运行规则

每次审核单同时保存为 `reports/review-YYYY-MM-DD.md`，便于引用具体批次。当天重复生成时，同一证据版本的决定和备注会保留；版本变化会回到待审核。已收录文章不重复进入新审核单。未通过项目保持在候选库中，可在以后的批次继续处理。

自动周更没有收录权限。代码层面，收录入口必须显式提供 `--approval-file`，只接受决定为“通过”且证据版本匹配的条目；该参数不会由每周任务传入。模型建议不能充当人工批准。审核文件应在你明确交给助手处理后使用，而不是由定时任务自动执行。

## 筛选偏好与已审核条目

当前优先方法学和原始公平性审计；综述仅在具体疾病/任务上有详细医疗算法公平性分析时考虑，详见[筛选规则](screening-policy.md)。已排除且内容未变的条目不再反复送审，排除理由保留在 `data/curation-decisions.json`。人工批准可覆盖初筛建议，但会明确标注摘要级/全文级证据，综述和评论不改写为原创实验。
