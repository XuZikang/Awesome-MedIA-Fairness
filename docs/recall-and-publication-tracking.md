# 补漏检索、召回回归与出版版本追踪

## 三个独立步骤

1. **召回回归**：`config/recall-sentinels.json`保存6个已批准方法论文和2个反例；题名和描述取自公开目录。`python3 -m scripts.recall`验证共享补漏词表能否覆盖这些样例。移除必要词族会产生失败，周更在检索前检查；失败不发布新一轮报告。本地词表检查不等于真实API成功，也不是检索查全率估计。
2. **独立补漏通道**：`config/recall.json`按医疗语境、数据集别名、一般算法语境及公平性／偏差机制词生成查询。允许公平性只出现在摘要中，不要求某一种具体方法词。保留计算方法或相关数据集语境，避免把所有医疗社会不平等或观察性混杂研究都当作算法公平性候选。每个来源两组补漏查询，合计6组，与原有9组方法学和2组综述查询并行；查询哈希和失败区间各自独立。跨通道命中仍去重，`discovery_lanes`保留发现路径。
3. **出版身份追踪**：定期按已知arXiv ID检查明确DOI／期刊引用，再用Crossref登记关系或已明确提供的DOI核对。缺少关联时可检索可能同题正式版本；题名搜索结果只列为待核实，不能仅凭同名或同作者自动合并。Crossref `is-preprint-of`／`has-preprint`登记关系，或明确arXiv DOI且正式记录题名与首作者吻合，才生成确认关联。

默认每周检查至前一个完整UTC日。每次出版追踪最多20条，成功记录7天后再检查；失败保留既有确认关系和成功日期，记录重试状态并轮转队列，避免一次异常抹掉历史。全量历史身份检查有待办窗口，不会把一次有限检查宣称为全部完成。

## 身份、版本与人工决定

- 正式DOI、预印本DOI和arXiv基础ID可成为同一条记录的身份别名，但有冲突的现存记录不会自动删除或合并。
- 改题名线索、可能正式版本及冲突写入`reports/publication-tracking.md`，待人工核实；定时任务不修改README中的题名、日期、渠道或收录决定。
- 即使确认正式身份，也需要通过[渠道门槛](venue-policy.md)和主题证据审核。不能把不合格正式版本重新包装成预印本收录。
- 模型筛选只是建议；新增文章仍必须由维护者明确批准。已确认的旧目录和人工拒绝不会因检索通道或展示规则变化而被清除。
- 已发表论文的渠道元数据只从论文自身的期刊字段读取，不读取其参考文献的期刊和DOI。

## 输出与故障

`reports/recall-regression.md`展示样例结果，`reports/publication-tracking.md`展示身份线索，`reports/venue-policy.md`保存渠道判断，`reports/review-latest.md`供人工决定。`reports/run-status.json`分别记录来源检索完整性、机器分析、人工审核、渠道状态及出版追踪，不以任一阶段替代其他阶段。

PubMed会拒绝部分未索引的数据集词或包含停用词的表达式；这些源特定省略项在补漏配置中明确列出，不静默删除整个查询。API失败、分页未完整或模型额度不足时，候选和诊断仍保留，不自动推进失败查询的检索检查点、不自动纳入论文。Qoder接口沿用原配置，不因故障切换提供方。

机器检索候选、已核实正式身份和人类批准是不同状态。代码与离线测试通过不表示外部模型已经恢复；实际来源调用结果应单独记录。

## 运行

```bash
python3 -m scripts.recall --output reports
python3 -m unittest discover -s tests -q
python3 scripts/validate_catalog.py
```

主CLI默认启用配置中的补漏与身份追踪。`--metadata-only`跳过模型与全文调用，但仍可读取书目元数据；独立检索测试可用`--no-publication-tracking`。`--fixture`不会发起检索或身份联网请求，适合离线回归。
